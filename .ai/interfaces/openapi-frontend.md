The server exposes OpenAPI through `springdoc-openapi-starter-webmvc-ui`. The frontend `schema.ts` file is generated by `openapi-typescript`; endpoint modules alias its component schemas instead of maintaining parallel Java-shaped interfaces. The contract includes job, run, schedule, authentication, user, permission, and audit operations.

The project has tests for the server specification and generated-schema stability. Nullable Java response fields must be checked against serialized JSON because optional OpenAPI properties and JSON `null` are distinct representations. Framework implementation types should not leak into the public schema; deterministic DTO ordering supports drift checks.
