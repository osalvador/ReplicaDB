# Fix SqliteManagerNullHandlingTest (Issue #276)

## Context
NULL values become 0 in SQLite-to-SQLite replication. The fix (`wasNull()` checks) is in the current code.
The test that guards it is `@Disabled` because it used one SQLite file for both source and sink, causing locking.
Fix: rewrite the test to use two separate temp files - exactly the real-world scenario from issue #276.

#### Gap 1: sqlite-jdbc 3.41.2.2 rejects `YYYY-MM-DD` dates and timestamps without fractional seconds (Plan-to-Implementation)
- **Task**: 1.1b (added mid-execution)
- **Plan assumed**: `SqliteManager` DATE/TIMESTAMP handling was complete after the February 2026 wasNull() fix
- **Reality**: The proposal explicitly called for a string-parsing fallback for DATE/TIMESTAMP but it was never applied; sqlite-jdbc 3.41.2.2 throws `ParseException` for `current_date` output ("2026-08-12") and for timestamps without fractional seconds
- **Resolution**: Added try-catch with `Date.valueOf()` / `Timestamp.valueOf()` fallbacks in `SqliteManager.insertDataToTable`
- **Learning**: Always cross-check the proposal's "Replace with" blocks against the actual implementation before marking a phase complete

#### Gap 2: sqlite-jdbc does not implement `getBlob()` / `getClob()` (Plan-to-Implementation)
- **Task**: 1.1b (discovered during the same iteration)
- **Plan assumed**: `getBlob()` / `getClob()` API calls are standard JDBC and work with all drivers
- **Reality**: sqlite-jdbc throws `SQLFeatureNotSupportedException` for `getBlob()` (and by extension `getClob()`); these were hidden because the test was previously disabled
- **Resolution**: Replaced `getBlob()` with direct `getBytes()` and `getClob()` with direct `getString()`
- **Learning**: SQLite's BLOB/CLOB JDBC surface is intentionally minimal - always use `getBytes()`/`getString()` for binary/text LOBs

#### Gap 3: `getBigDecimal()` on NULL in sqlite-jdbc 3.41.2.2 does not set `lastColumn` (Plan-to-Implementation)
- **Task**: 1.1 (test assertion style)
- **Plan assumed**: The `getBigDecimal(col); wasNull()` assertion pattern used in OracleManager/StandardJDBC tests works universally
- **Reality**: sqlite-jdbc's `getBigDecimal()` for a NULL value does not update the internal `lastColumn` field, so `wasNull()` immediately after throws "column -1 out of bounds"
- **Resolution**: Changed the BIGINT/NUMERIC assertion to `assertNull(rs.getBigDecimal(1))`, which does not depend on `lastColumn`
- **Learning**: Do not assume `getPrimitive(); wasNull()` round-trips correctly across all JDBC drivers - `assertNull(getObject())` is safer for object types
